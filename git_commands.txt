1. git init
   Creates the hidden .git tracking directory inside git-workflow-project to turn the local folder into a version-controlled repository.

2. git add <file>
   Moves specified files (such as index.html, about.html, and .gitignore) into the staging index before recording a commit.

3. git commit -m "<message>"
   Saves all currently staged modifications permanently into the local repository history along with a summary note.

4. git branch <branch-name>
   Sets up a separate development line named 'feature' so edits can be tested independently from the main codebase.

5. git checkout <branch-name>
   Switches the active working tree between the 'main' and 'feature' branches.

6. git merge --no-ff <branch-name>
   Combines the completed edits from the 'feature' branch back into 'main' while recording an explicit merge commit.

7. git log --oneline --graph --all
   Prints a condensed ASCII branch diagram displaying every commit hash, branch pointer, and merge across the project.

8. git status
   Checks which working files are staged, modified, or successfully excluded by .gitignore (such as app.log and temp/).

9. git revert HEAD
   Reverses the changes introduced in the previous commit by generating a new follow-up commit that restores the prior file state.

10. git remote add origin <url>
    Links the local project folder to the remote GitHub repository (kondetiv59/git-workflow-assignment) under the name 'origin'.

11. git push -u origin main
    Transfers all local commits on the 'main' branch up to GitHub and sets 'origin/main' as the default upstream target.
